ПОЛНОЕ ПОДРОБНОЕ ОПИСАНИЕ СИСТЕМЫ TESTS (TRACE MODE 7)
Версия документа: 2026-03-14
Актуально для проекта: tests_app / TESTS.exe

===============================================================================
1. ОБЩЕЕ НАЗНАЧЕНИЕ СИСТЕМЫ
===============================================================================
Система TESTS — это офлайн-приложение на Windows Forms для проверки знаний
по TRACE MODE 7 и связанным темам АСУТП.

Ключевые задачи системы:
1) Проводить тестирование студентов без интернета.
2) Давать преподавателю интерфейс редактирования тестов и вопросов.
3) Хранить данные локально в защищенной БД.
4) Автоматически формировать итоговый тест из уровней 1–4.
5) Работать переносимо между компьютерами при копировании папки Release.

===============================================================================
2. СОСТАВ ПРИЛОЖЕНИЯ
===============================================================================
Основные формы:
1) start (главное меню):
   - выбор теста;
   - запуск прохождения;
   - переход во вход преподавателя.
2) test_panel (прохождение теста):
   - таймер;
   - навигация по номерам вопросов;
   - ввод ответов;
   - досрочное завершение;
   - показ результата.
3) admin_login (вход преподавателя):
   - проверка логина/пароля.
4) admin_panel (панель преподавателя):
   - просмотр тестов/вопросов;
   - добавление/редактирование/удаление;
   - просмотр правильного ответа (если ответ зашифрован и доступен).
5) редакторы вопросов/тестов:
   - QuestionEditorForm;
   - TestAdd;
   - TestEditorForm.

Служебные классы:
1) TestStorage.cs — слой доступа к БД и синхронизации тестов.
2) SecurityService.cs — безопасность (хэши, шифрование ответов).
3) DefaultTestCatalog.cs — встроенный каталог вопросов по уровням.
4) Models.cs — модели Test и Question.
5) UiTheme.cs — адаптивная типографика и визуальный стиль.

===============================================================================
3. СТРУКТУРА ТЕСТОВ
===============================================================================
В системе 5 тестов:
1) tm7-level-1
2) tm7-level-2
3) tm7-level-3
4) tm7-level-4-5
5) tm7-final-advanced (итоговый)

Логика объема:
1) В каждом из уровней 1–4:
   - 50 вопросов в банке;
   - 30 single;
   - 12 multiple;
   - 8 text.
2) В итоговом:
   - автоматически собирается из всех вопросов уровней 1–4;
   - ручные вопросы преподавателя в итоговом сохраняются отдельно;
   - общее количество зависит от текущего состояния уровней 1–4 и ручных
     вопросов итогового.
3) В одной попытке студенту дается 20 вопросов.
4) Время попытки: 20 минут.

4. МОДЕЛЬ ДАННЫХ
===============================================================================
Сущность Test:
1) Id (string)
2) Title (string)
3) Description (string)
4) TimeMinutes (int)
5) Questions (List<Question>)

Сущность Question:
1) Id (string)
2) Text (string)
3) Type (QuestionType)
4) Options (List<string>)
5) Answer (string) — временное поле для открытого ответа, в норме очищается
6) AnswerEncrypted (string) — основной формат хранения правильного ответа
7) FinalSourceKey (string) — служебный ключ для итогового теста
8) AnswerHash (string) — legacy-поле
9) AnswerSalt (string) — legacy-поле

Типы вопросов QuestionType:
1) Single
2) Multiple
3) Text

5. ХРАНЕНИЕ И БАЗА ДАННЫХ
===============================================================================
Тип БД:
1) LiteDB (файл tests_secure.db)

Коллекция:
1) tests

Местоположение по умолчанию:
1) рядом с TESTS.exe (обычно bin/Release или bin/Debug)

Что делает TestStorage:
1) Инициализирует БД при первом запуске.
2) Загружает тесты и нормализует поля.
3) Сохраняет тесты обратно в БД.
4) Шифрует ответы перед сохранением (через SecurityService).
5) Удаляет legacy-файлы tests.enc/tests.json/tests_debug.json.
6) Обновляет встроенный каталог, если обнаружена устаревшая версия.
7) Синхронизирует итоговый тест из 1–4.
8) Удаляет дубликаты вопросов.

===============================================================================
6. БЕЗОПАСНОСТЬ: ЧТО ЗАЩИЩЕНО И КАК
===============================================================================
6.1. Вход преподавателя
1) Логин/пароль не хранятся в открытом виде в коде формы.
2) Хранятся соль+хэш (PBKDF2-SHA256).
3) Проверка делает SecurityService.VerifySecret(...).

6.2. Правильные ответы
1) Основной режим хранения: только в AnswerEncrypted.
2) Answer шифруется и очищается.
3) Hash-ветка legacy оставлена только для совместимости.
4) Проверка ответа:
   - расшифровка AnswerEncrypted;
   - канонизация;
   - сравнение с ответом пользователя.

6.3. Шифрование базы
1) LiteDB открывается с паролем.
2) Это защищает файл tests_secure.db от простого чтения.

6.4. Ограничения модели безопасности
1) Это офлайн-клиент, значит абсолютной защиты от реверса нет.
2) Усиление сделано на уровне:
   - шифрования БД;
   - шифрования ответов;
   - закрытого админ-входа по хэшам;
   - крупного пула вопросов и случайной выборки.

===============================================================================
7. АЛГОРИТМ ИТОГОВОГО ТЕСТА (КЛЮЧЕВОЕ ПОВЕДЕНИЕ)
===============================================================================
Цель:
1) итоговый должен отражать 1:1 актуальное содержимое уровней 1–4.

Как это работает:
1) При загрузке/сохранении вызывается синхронизация итогового.
2) Система берет текущие вопросы из тестов:
   - tm7-level-1
   - tm7-level-2
   - tm7-level-3
   - tm7-level-4-5
3) Генерирует авто-часть итогового на базе этих вопросов.
4) Ручные вопросы итогового (добавленные преподавателем прямо в итоговый)
   сохраняются и добавляются к авто-части.
5) Применяется дедуп.

Следствие:
1) Изменение вопроса в тесте 1–4 изменяет авто-часть итогового.
2) Добавление вопроса в тест 1–4 добавляет его в итоговый.
3) Удаление вопроса из теста 1–4 убирает его из авто-части итогового.
4) Ручные вопросы итогового не исчезают.

===============================================================================
8. УНИКАЛЬНОСТЬ ВОПРОСОВ
===============================================================================
8.1. Уникальность в БД
1) При нормализации для каждого теста применяется дедуп.
2) Дедуп-ключ: тип вопроса + нормализованный текст.
3) Это убирает дубли с одинаковым смысловым текстом.

8.2. Уникальность в итоговом
1) При сборке итогового авто-часть тоже дедуплицируется.
2) Ручные вопросы фильтруются, если совпадают с авто-частью.

8.3. Уникальность в попытке (20 вопросов)
1) test_panel выбирает случайные вопросы из пула.
2) Проход №1:
   - пытается выбрать максимально разные "семейства".
3) Проход №2:
   - если 20 не набрались, добирает уникальными вопросами по отпечатку.

Что такое "семейство":
1) Для Single-вопросов ищется термин в кавычках «...».
2) Если термин найден, семейство = этот термин.
3) Если нет — семейство = тип + нормализованный полный текст.

Практический эффект:
1) Похожие вопросы по одному термину не идут подряд.
2) Полные повторы формулировки в одной попытке исключаются.

16. ТИПОВЫЕ ПРОБЛЕМЫ И РЕШЕНИЯ
===============================================================================
Проблема: БД не открывается в Studio.
Причина:
1) неверный пароль;
2) файл занят запущенным приложением.
Решение:
1) проверить пароль;
2) закрыть TESTS.exe и повторить.

Проблема: Не обновились формулировки встроенных тестов.
Причина:
1) БД занята процессом;
2) запуск шел из другой папки (Debug/Release путаются).
Решение:
1) закрыть все экземпляры TESTS.exe;
2) запускать из нужной папки;
3) проверить, какой tests_secure.db реально используется.

Проблема: В итоговом вопрос не появился.
Причина:
1) вопрос не сохранен в исходном тесте;
2) дубликат отфильтрован дедупом.
Решение:
1) убедиться, что вопрос есть в тесте 1–4;
2) изменить формулировку, если это дубль.
